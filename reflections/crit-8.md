# Crit 8 — making participation the entry point

> Reflection prepared with AI assistance, 2 October 2026. Based on the recorded project direction; not a report of an attended crit or tutor feedback. The student must decide whether the first-person interpretation below matches their experience.

## What was the breakthrough that moved the work forward?

The useful breakthrough was separating the visitor's task from the organiser's task. A poster editor assumes somebody arrives already wanting to create something. A campus wall also serves somebody who only wants to find an activity. Giving guests a public browsing route made the project easier to explain: discover first, contribute when there is a reason.

That distinction also clarified the data model. A private working draft and a published notice have different audiences. Saving an edit should preserve work; publishing should deliberately change what others see. Treating those as separate actions provides a better foundation than adding more templates to an unclear workflow. The current implementation and its tests preserve that distinction, although they do not prove that students will find the notices useful.

## What did this work change about who I want to be as a software developer?

The direction I want to develop is asking who can complete a meaningful task before asking which feature to add. An agent can produce an impressive editor quickly, but choosing the entry point still needs product judgement. I would like to become more deliberate about turning that judgement into rules the implementation must respect. My next evaluation should involve someone browsing without coaching, so that convenience is tested through behaviour rather than inferred from a polished screenshot.
